# LSTM Forecasting Backend — Validation Report
- **Target**: `lstm_forecasting_analysis.py` · **Endpoint**: `/api/analysis/lstm-forecast`
- **Method**: every deterministic part of the pipeline rebuilt independently — data cleaning and date ordering, the supervised windowing and train/test split, the test actuals value-by-value, and the test RMSE / MAE / R² recomputed from their formulas on the handler's returned test predictions; run-to-run reproducibility; forecast horizon, dates and finiteness. Runs in the pinned deploy environment (`requirements.txt`: tensorflow-cpu, numpy<2, Python 3.11).
## Summary
LSTM training is a stochastic deep-learning fit with no closed-form reference, so validation targets what can be checked deterministically. The input arrives shuffled, with one unparseable date and one missing value; the handler must drop both and sort by date. The `(n − window)` supervised windows and the `int((n − window)·(1 − test_size))` train/test split are rebuilt independently, and the returned test actuals must equal the raw series at the test-window targets, value-by-value. Test **RMSE, MAE and R²** are recomputed with numpy from their formulas, using those independently built actuals and the handler's returned test predictions (`results['_validation']['y_pred_test']`). Two runs on identical input must return identical test predictions and forecasts. The forecast must have the requested horizon, finite values, and dates that continue the monthly calendar from the last observation. Naive (t−1) and seasonal-naive (t−12) baselines are printed for context only — the handler does not report a baseline to compare. Train-set metrics are only checked for finiteness, since the handler does not return the train predictions they come from. Where TensorFlow is not installed the script skips with zero checks.

**Bug found & fixed during validation**: the handler's fixed seed did not take effect. It called `tf.random.set_seed(42)`, which under Keras 3 (installed with tensorflow 2.16+) does not seed the Keras weight initializers or Dropout, so two runs on identical input returned different test predictions and forecasts. The handler now calls `tf.keras.utils.set_random_seed(42)`, which seeds Python, NumPy, TensorFlow and Keras together; the reproducibility checks fail on the old handler and pass on the fixed one.

**Earlier fix**: the endpoint failed every request with *"Missing required parameters: data, timeCol, or valueCol"* — the handler only read camelCase keys while the frontend sends snake_case (`date_col`/`value_col`/`window_size`/…). The handler accepts both naming conventions, and TensorFlow/oneDNN/absl startup chatter is silenced so it no longer leaks into the endpoint's error surface.
## Defects — Fixed the ineffective seed (fits were not reproducible), the parameter-name mismatch (endpoint was fully broken) and the stderr log leakage. Repro: `validation/validate_lstm_forecasting.py` in the pinned environment.
